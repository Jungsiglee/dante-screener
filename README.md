# 급등 초입 스캔

주식단테 채널의 256기법 / 이평때리기 계열 조건으로 전 상장사를 매일 훑고,
결과를 아이폰 사파리에서 PWA로 보는 도구. **서버 없음, 비용 없음.**

```
GitHub Actions  매일 16:10 KST cron
  prices.py   pykrx 일봉 증분 수집 (Actions 캐시)
  build_db.py DART 재무 (분기 1회)
  scan.py     이평선 계산 → 조건 판정 → docs/result.json 커밋
        ↓
GitHub Pages  (main 브랜치 /docs)
        ↓
아이폰 사파리 → 공유 → 홈 화면에 추가 = 앱처럼 실행, 오프라인에도 마지막 결과 표시
```

## 셋업

1. **공개 저장소**로 만든다. 비공개는 Actions 분이 제한되고 Pages 도 유료 플랜이 필요하다.
   코드가 공개되므로 API 키는 절대 커밋하지 말 것.
2. 이 파일들을 올린다.
3. Settings → Secrets and variables → Actions → `DART_API_KEY` 추가 (재무 점수를 쓸 때만).
4. Settings → Pages → Source: `main` 브랜치 / `/docs` 폴더.
5. Actions 탭 → daily scan → **Run workflow** 로 첫 실행.
   첫 실행은 일봉 전체 백필 때문에 10~20분 걸린다. 이후는 1~2분.
6. 아이폰 사파리로 `https://<계정>.github.io/<저장소>/` 접속 → 공유 → 홈 화면에 추가.

## 조건과 점수

| 조건 | 판정 | 배점 |
|---|---|---|
| 256 골든크로스 | 최근 3거래일 내 MA5 가 MA20 상향돌파 | 30 |
| 112 안착 | 종가가 MA112 위로 올라와 3일 연속 유지 | 20 |
| 224 돌파 | 종가가 MA224 상향돌파 | 15 |
| 장기 역배열 | MA112 < MA224 < MA448 | 10 |
| 바닥 이력 | 250일 고점 대비 -35% 이상 하락 경험 | 10 |
| 거래량 급증 | 당일 거래량 ≥ 20일 평균 × 1.5 | 15 |

재무 점수(최대 25): 매출 3년 CAGR 백분위 0~10, 영업이익 3년 CAGR 백분위 0~10,
흑자전환 +5, 적자전환 −10. **자산증가율은 점수에 넣지 않았다** — 부채와 유상증자로도
오르기 때문에 급등 신호로서 방향이 모호하다. 화면에는 참고용으로만 보여준다.

손절/목표는 단테 기법의 규칙 그대로: 손절 = 20일선, 1차 목표 = 60일선, 2차 = 112/224일선 중 높은 쪽.

## 검증 상태

**검증됨** (합성 일봉 480거래일 × 44종목으로 확인):
- 이평선 계산, 6개 조건 판정, 점수 합산, JSON 출력
- 역배열·거래량 플래그가 실제 수치와 일치
- 프런트가 전 항목을 오류 없이 렌더 (undefined/NaN 누출 0건)
- 워크플로 YAML, 파이썬, JS 문법

**미검증 — 첫 실행 때 반드시 확인할 것:**
1. **GitHub Actions 러너는 해외 IP다.** KRX(pykrx)와 DART가 해외 IP를 막을 수 있다.
   DART 는 에러코드 012(접근할 수 없는 IP)로 나타난다. 이게 이 설계 전체의 단일 실패점이다.
   막히면 → 집 PC 작업 스케줄러나 오라클 VM 으로 수집만 옮기고, Pages 는 그대로 쓴다.
2. pykrx 컬럼명. `prices.py` 는 `종가`/`거래량`을, `meta` 는 `종목명`/`시가총액`/`거래대금`을
   찾는다. 버전에 따라 다르면 그 줄만 고치면 된다.
3. 예약 워크플로는 저장소 활동이 60일간 없으면 자동 비활성화된다. 봇 커밋이 활동으로
   인정되는지 확실치 않으니, 두 달쯤 뒤 Actions 탭이 멈춰 있지 않은지 한 번 볼 것.

## 조정

`scripts/scan.py` 상단 상수를 바꾸고 Run workflow 하면 끝이다.

```python
SETTLE_DAYS = 3      # 안착 판정 연속일수
DRAWDOWN = -0.35     # 바닥 판정 낙폭
VOL_MULT = 1.5       # 거래량 배수
CROSS_RECENT = 3     # 크로스 유효기간
WEIGHTS = {...}      # 배점
```

**이 숫자들은 제가 임의로 정한 출발점이다.** 원 기법의 '안착', '바닥' 에는 수치 정의가
없어서 누군가는 정해야 했을 뿐이고, 어느 값이 맞는지는 백테스트로만 알 수 있다.
지금 나오는 점수는 "조건에 몇 개 걸렸나"이지 "얼마나 오를까"가 아니다.
